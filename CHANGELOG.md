# Changelog

## Unreleased (changes since `v0.1.0-alpha.3`)

- No local model is required: rules-mode drafts are marked partial and `[auto-drafted]`, quote bounded conversation text, are screened, and remain private until reviewed. An optional local model remains available. See [setup without a local model](docs/adapters/setup.md#set-up-without-a-local-model).
- `wk-agent prompt --client claude-code|copilot|codex` creates `/wk-summarize` instructions for assistant-written cards; `wk-agent draft` validates and stores them as private drafts for 24 hours. Nothing reaches the team server before review, and a reviewer can then publish them: cards carry a new optional `provenance` (`assistant_written`), the policy advertises `card_provenance`, and `knowledge.record` refuses the field. Upgrade the server before collectors; an older server receives a plain partial draft. Rule drafts, hook partials, imports and truncated cards remain unpublishable. See [Summarize with your assistant](docs/adapters/setup.md#summarize-with-your-assistant-wk-summarize).
- Behavior change: `wk-agent init` and `wk-agent device connect` without `--inference` now select `rules`. Existing configurations remain `local`; rules configurations contain a key older binaries cannot read. A setup's summarizer mode cannot be changed in place.
- New `WK_OIDC_CA_FILE` setting lets the server use an identity provider behind a private certificate authority (previously only public CAs were trusted). The [Keycloak guide](docs/operations/oidc-keycloak.md) records the audience rules and the local qualification; the collector side is `wk-agent device connect --ca-file` (below).
- `wk-agent device connect --ca-file PEM` lets the native collector use a hosted server and identity provider behind a private certificate authority. The validated bundle (certificates only, at most 64 KiB) is stored in private collector state and replaces the public roots for server and provider requests only, with no fallback; existing collector state and approval receipts are unchanged. `wk search` and `wk-mcp` read an explicitly set `WK_SERVER_CA_FILE` the same way. `device status` reports `server_trust`.
- Summary quality: the setup guide and README now recommend the assistant-written flow (`/wk-summarize`) with rule drafts as the zero-setup fallback. Rule drafts no longer use a greeting, a pasted trace or code fence, or a bare "ok do it" as the title (45% of cards on a synthetic 20-turn comparison), drop closing courtesies from the rationale and, for replies over 1,500 characters, start at an "In summary"/"TL;DR" paragraph. [`scripts/summary-quality-eval.py`](scripts/summary-quality-eval.py) and the [comparison](docs/reviews/2026-10-19-summary-quality-comparison.md) record the measurement and its limits, including that partial (assistant-written and rule) cards cannot be published.
- Contact-detail screening no longer mistakes UUIDs, hashes and dates for phone numbers (it could intermittently reject legitimate summaries).

## v0.1.0-alpha.3 — source-only prerelease (2026-10-17)

Published as a GitHub prerelease while the repository was private. Tag `v0.1.0-alpha.3` points to commit [`5b982a5`](https://github.com/DharanesshMD/workspace-knowledge/commit/5b982a5f4523d1e017de4d190586c715538abbe9). It supersedes alpha.1 and alpha.2; no binaries are attached. The tag predates current `main` and is an evaluation candidate, not a production-supported release. See the [release notes](https://github.com/DharanesshMD/workspace-knowledge/releases/tag/v0.1.0-alpha.3).

Known limits at alpha.3 included partial, version-pinned capture; a failed strict model-sensitive contact case; no production OIDC/HTTPS qualification, real-team target-server pilot, long-duration capacity result, signed/notarized macOS distribution, or production security certification. Automatic publication was and remains disabled. See the [production readiness ledger](docs/operations/production-readiness.md) for current status.
