## Global Constraints

- Do not make the repository public, tag/publish a release, or advertise production certification while gates are open.
- Do not capture real conversations, use valued databases, mutate global client profiles or expose credentials in audit logs.
- All database verification uses an owned disposable `wk_test` fixture.
- Retain unverified supported-host edit protection, capture coverage and native startup as explicit gates.
- Do not suppress runtime RUSTSEC-2023-0071. Analyze applicability without replacing the established OIDC protocol implementation speculatively.
- Platform release scope is Linux server + macOS collector; other platforms remain build targets unless separately accepted.
- Push the reviewable candidate and open a draft PR under the user's ongoing integration authorization; do not merge unreviewed runtime code into main.

## Review Focus

- Main's green CI does not certify feature-branch runtime changes: test the candidate's exact commit.
- History scanning must redact secret values; fixture findings require individual review rather than a directory-wide suppression.
- Audit tooling failures must remain failures, including failure to resolve the dependency graph.
- A dependency present in normal runtime cannot be labeled dev-only.
- Local identity/restore/load fixtures do not satisfy the user-deferred production OIDC gate.
