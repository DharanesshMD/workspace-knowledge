# Optional private hybrid search

Approved intent: improve discovery of other developers' recorded rationale when a question uses different wording. The user selected pgvector in existing PostgreSQL and explicitly requested implementation. Preserve workspace privacy, reviewed publication, current membership and verified attribution. Similarity is discovery evidence, never authorship, dependency or edit permission.

## Storage and compatibility

Keep core migrations1–17 and plain PostgreSQL installation unchanged. An explicit owner-only `semantic-migrate` command installs a separate optional schema after the deployment installs pgvector0.8.7. Existing deployments do not need the extension. A separate optional grant script gives the runtime SELECT only on semantic tables. Runtime initialization/search never performs DDL. Optional Compose override pins the pgvector Postgres17 image; no automatic existing-volume conversion or model download occurs in application startup.

`card_embeddings` stores org/product/card/revision, model digest, model name, dimension, format version, vector and bounded retry status. Model name/digest/dimensions/format form the namespace. Only published, nonwithdrawn, nonsuperseded/nondeprecated card revisions are eligible. Index writes recheck those predicates and exact source revision after slow inference. Drafts, personal summaries, raw conversations, environment values and contributor contact fields are not read by the indexer. Index text includes title, intent, rationale, decisions, constraints and open questions only. No automatic truncation: excessive input is held. A card-change trigger removes its derived vectors when revision/publication/withdrawal changes; withdrawn/superseded/old revisions are additionally excluded at read time. Backup vectors are untrusted derived data and never establish current visibility.

Use exact cosine distance over SQL-permitted current cards with an initial Nomic cosine-similarity floor0.6 (a retrieval heuristic, not a correctness/confidence claim); no approximate global index in V1. RLS is defense in depth, plus explicit organization/product/user/every-service filters before returned candidates. Standard runtime roles cannot insert/update/delete vectors or namespace policy. Operator indexing is bounded to20 records per pass, with failed items backed off five minutes; successful unchanged revisions are not embedded again. Old model namespaces are pruned by the operator when indexing a replacement. No persistent query or result cache.

## Private embedding provider

Initially support the native Ollama `/api/embed` API on literal loopback HTTP only. Proxies, redirects, URL credentials/query/fragment and arbitrary public/private network destinations are refused. The app and model must share a host/network namespace; remote endpoints require a later reviewed extension. Explicit `WK_EMBEDDING_URL`, `WK_EMBEDDING_MODEL`, `WK_EMBEDDING_DIGEST`, `WK_EMBEDDING_DIMENSIONS` enable the feature; all unset leaves it disabled. Partial/malformed configuration refuses startup. Digest must be64 lowercase hex characters, dimensions1–2048, model a bounded ASCII model identifier. First evaluated model: `nomic-embed-text:v1.5`,768 dimensions, `nomic-search-v1` query/document prefixes. This prefix policy is namespace-bound.

Before and after embedding, bounded `/api/tags` metadata must bind the configured model name to its approved digest. Model changes fail closed for semantic computation and fall back to lexical retrieval. `/api/embed` uses `truncate:false`; validate exact output model/count/dimensions, finite nonzero vectors and body size. Client has2 concurrent operations, no queued overload, a3-second total query deadline and30-second indexing deadline. Content-free errors/status only; no prompt/vector/text logging or application tokens sent to the provider. Provider/host operators remain trusted; metadata checks are not cryptographic model certification.

## Retrieval and user experience

Expose one shared search function to HTTP and remote MCP; stdio MCP already uses HTTP. Authorize product membership before sending a query to the embedding provider, screen queries, then revalidate permissions in final SQL. Read no more than20 semantic and20 keyword candidates. Rank keyword candidates by PostgreSQL text relevance with stable ID ties; semantic candidates by cosine distance with stable ID ties. Fuse ranks with reciprocal rank fusion constant60; deduplicate by card ID, return at most requested1–20 cards. Do not assign a truth/confidence interpretation to similarity.

Add bounded `retrieval` diagnostics alongside cards: lexical/hybrid mode and fixed-label fallback reason. Missing extension/schema, missing current vectors, changed model, provider error/deadline/capacity yield lexical fallback. Never hide DB/authorization errors as semantic success. UI shows retrieval mode/fallback for a completed search; MCP search/context retains diagnostics so agents know which path ran. Existing response fields/tools remain compatible. File/revision change briefs, protected edits and overlap notices keep their established behavior; semantic search can discover a reference but does not automatically anchor it to a file.

## Acceptance

Use an owned disposable pgvector/Postgres17 database and synthetic local model fixture. Test restricted runtime RLS, unauthorized nearest neighbors/other tenants, revoked membership, mixed services, unpublished/private records, stale/corrected/withdrawn/superseded vectors, model/dimension mismatch, runtime write denial, indexing race and bounded retries. Test local HTTP protocol, redirects, oversized/malformed/model-change/zero/nonfinite/dimension responses, timeout/capacity and sensitive queries before provider use. Exercise HTTP and both MCP transport paths and UI diagnostics. Run existing Rust/Postgres, Python and browser suites/build/audits.

Evaluate real local embeddings on a committed synthetic feature-reuse corpus against keyword search, including paraphrases, exact identifiers and distractors. Record recall/ranking and measured local latency, with no invented deployed-server capacity claim. Keep semantic search optional regardless of benchmark outcome; representative team quality and production model capacity remain qualification work. No publication, merge, real-data indexing or deployment is authorized by this increment.
