# v0.1 local acceptance continuation

This continues the private draft candidate for **Linux Docker server + macOS developers**. The user chose local fixtures; production OIDC, a real target-server/team pilot and Apple signing/notarization remain pending. It is not a published or production-certified release.

## Reproduced defects and fixes

- Windows child PowerShell inherited PowerShell Core module paths through Rust and could not load `Microsoft.PowerShell.Security`. Removing `PSModulePath` only in the ACL child command fixed the observed failure without changing owner/ACL rules. At commit `2677b3a`, all foundation CI jobs passed, including Windows directory creation/reopening, inherited-directory rejection and the pause regression. The temporary standalone diagnostic was removed after these native regressions passed.
- Explicit signed repository enrollment changed collector configuration without refreshing its approved device receipt. Refreshing the receipt after that authorized enrollment restored the native protection flow; arbitrary configuration changes remain rejected.
- A pending preflight prevented membership revocation because its binding foreign key restricted the membership-to-binding deletion cascade. Migration **17** cascades deletion of temporary preflights. A real PostgreSQL regression covers operator and scoped-administrator revocation, consumed authority loss and no resurrection after regrant. Backup, restore and readiness now require migrations **1–17**; migration 16 was not rewritten.
- The actual local Qwen model accepted an instruction-framed synthetic input. Common override phrases are now held before inference, including case/whitespace variants. This is conservative screening with false positives and known incompleteness, not proof against all prompt injection. Shared submissions using the same markers are rejected too; retrieval remains untrusted reference data. Automatic publication remains disabled.

## Local model and recovery

`cargo run --locked -p wk-summarize --example privacy_acceptance -- http://127.0.0.1:11434/api/chat qwen3.5:2b` exercises **six synthetic samples** against actual Ollama inference. Local model: `qwen3.5:2b`, digest prefix `0689d44085e0`. The technical rationale was retained as **proposed/partial**. Credentials/outside-home references/instruction framing were held by application source screening; the fictional medical detail was explicitly flagged sensitive by the model. For the fictional contact detail, the model did **not** provide the required sensitive flag; application output screening instead held it for the `keyword:personal` rule. No private sample was accepted in this observed run, and publication was never attempted, but the strict **model-sensitive corpus failed** and remains a gate.

The fresh reviewer reproduced a false-green defect in the original harness: arbitrary provider errors counted as successful holds. That result is superseded. The corrected harness requires exact deterministic reasons or an explicit model-sensitive flag, exits nonzero for failures, and reports only fixed rejection labels. Three fixture regressions distinguish HTTP500/malformed output from a privacy decision and verify deterministic/model holds. This small corpus does not certify arbitrary personal information, other models or capture; automatic publication remains disabled.

The schema-17 encrypted restore drill passed all **14** reported checks on PostgreSQL 17.11 and age 1.1.1: authority/session/device/preflight quarantine, PUBLIC helper restriction, newest shared and private deletion journals, orphan-key preservation, repeat merge, nonempty refusal, interrupted rollback, tampered ciphertext and incompatible manifest rejection. Every database was newly created and disposable.
