## Narrow scanner exceptions

`.gitleaksignore` contains five original commit/file/rule/line fingerprints. `.gitleaks.toml` extends every default rule and adds one exception requiring BOTH the exact personal-test path and the complete, literal reviewed synthetic source line (allowing whitespace/diff-prefix variation). This prevents repeated false findings when that same canary is inherited by merge commits. There is no directory or file-wide allowance, and no pattern matching arbitrary tokens.

- `crates/knowledge/tests/personal.rs`: a literal synthetic secret used to test rejection of sensitive private notes.
- `crates/adapters/tests/cursor_history.rs`: a literal synthetic token used by the redaction regression.
- `crates/adapters/tests/support/cursor_fixture.rs`: a literal synthetic token in an owned fake Cursor record.
- `crates/server/tests/fixtures/synthetic-rsa-a.json` and `synthetic-rsa-b.json`: test-only keys with an explicit warning never to trust them in deployments. Consumers are authentication/native-login tests and owned synthetic identity/load harnesses.

New credential values remain findings, including generic keys added only by a merge in the same personal-test file. Both the unchanged-byte check and merge traversal have adversarial regressions. Reports were generated with `--redact=100`; values are not published. An initial sequential placeholder canary was ignored by Gitleaks's built-in example filtering; the effective negative control used a fresh generated nonfunctional token. No real credential was validated against a provider, rotated or removed from history.

Pattern scanning is not a complete privacy review. Human review of historical screenshots, conversations, metadata and release artifacts remains a public-visibility gate.

## Runtime advisory applicability

`cargo tree -e normal` confirms `rsa 0.9.10 → openidconnect 4.0.1 → wk-server` and the equivalent collector chain. It is not a dev-only dependency. The OIDC consumer path inspected in openidconnect constructs an `RsaPublicKey` from JWK modulus/exponent and verifies signatures. Private test tokens use jsonwebtoken's AWS-LC backend in test/fixture code.

The [RustSec advisory](https://rustsec.org/advisories/RUSTSEC-2023-0071.html) describes private-key timing leakage and lists no patched version. Public-verification use narrows applicability but does not provide independent security clearance. The audit stays unsuppressed and candidate security CI deliberately rejects the remaining runtime dependency. Remediation or an explicit independent disposition is still required before release; no new homegrown OIDC implementation was introduced.

## Supported-host scope

[Sanitized case results](v0.1-readiness/claude-host-denial.json) and `scripts/code-context-host.py` make the native-host check reproducible. An isolated vendor executable was installed in private tooling; the existing global Claude 2.1.15 installation and user credentials/configuration were left unchanged. The harness strips inherited Claude/Anthropic settings, supplies a nonfunctional key and a loopback protocol fixture, and withholds client output on failure.

The baseline proves the host can actually write the synthetic target. The three guarded cases require real hook invocation and unchanged bytes. This verifies `Edit` denial, crashing-hook blocking and timeout blocking on 2.1.296. It does not certify `Write`/`MultiEdit`, cloud-backed agent operation, complete enrolled browser acknowledgement/retry, mixed context or shell/manual-write coverage. The installed protection remains `configured_unverified`.

## Independent review and one fix pass

One fresh reviewer found two Important issues and no Critical or Minor issues in the readiness increment. Both were reproduced before fixing:

1. The original scan omitted merge-only patches. An owned merge commit containing a generated nonfunctional token initially passed. The corrected production options include `-m`; a regression uses those exact workflow options and a new generic key in the same allowlisted test path. It must fail, with report values redacted.
2. The original host assertion treated any text other than the intended edit as unchanged. An adversarial synthetic client wrote `CORRUPTED` and initially passed. The corrected harness compares guarded targets with the original bytes, and the baseline with its exact desired bytes. The corruption regression now fails acceptance, while actual 2.1.296 denial/crash/timeout cases pass.

The stronger merge scan rediscovered the exact existing synthetic personal-note canary in the integration merge. Its source line was compared byte-for-byte with the originally reviewed fixture. A path-plus-whole-literal-line AND exception handles inheritance without hiding other keys; the same-path merge-only generic-key negative test passed. No second review or production clearance is claimed.

Current operational guides were corrected from schema 13 to the actual exact 1–16 readiness/backup/restore contract. Dated schema-13 acceptance records remain historical evidence rather than being rewritten.
