# Restore without silently reopening access

Keep API, workers and clients disconnected. Restore only into a new isolated empty database with no application network access. Set `PGSERVICE` to that target and run `deploy/scripts/restore.sh AGE_IDENTITY BACKUP.age --isolated-empty-database`. The script rejects populated targets, restores transactionally, removes ALL restored memberships, revokes workspace bindings and applies tombstones present in the backup. A failure leaves the target offline; do not start the app.

This cannot know about withdrawals or revocations after the backup. Obtain the latest independently retained tombstone ledger, merge it transactionally by org/product/card identity with maximum revision, and run `wk-server replay-tombstones` against the isolated restored target. Validate withdrawn cards and their historical revisions are inaccessible and indexes cannot return them. If the current ledger is missing or uncertain, leave restored data inaccessible; do not infer that an old backup is safe. External deletion-ledger replication and automated merge are not provided by this release.

Review current organizational policies from the authoritative source. Explicitly reprovision only currently authorized identities/memberships with `wk-server provision`; do not reload old membership snapshots. Workspace consent must be renewed. Restore vault independently, rotate credentials as necessary, revoke obsolete tokens and review current profile policies. Test two synthetic users plus revoked identities before reconnecting clients. Document exact PostgreSQL/vault/app versions, snapshot timestamps, latest ledger timestamp, elapsed recovery time and unresolved gaps. This procedure is fail-closed containment, not a claim of certified end-to-end disaster recovery.

The restore script now restores the dump and removes memberships in one transaction. Its access-removal queries explicitly use the `public` schema because pg_restore clears the search path. `tombstones.sh export/merge` encrypts and replays a separately retained latest deletion ledger. Run it before reprovisioning restored access.

The synthetic `scripts/restore-drill.py` test runs only against the disposable `wk-completion-postgres` container. It verifies encrypted snapshot restoration, empty membership state, a post-backup withdrawal recovered from the latest ledger, and refusal to restore over a nonempty database. The container must have PostgreSQL client utilities and age installed; no host credentials or production data are used.
