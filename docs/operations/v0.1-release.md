## Reproduce the supported-host boundary

Install a supported Claude executable separately in a test prefix, build `wk-agent`, then run:

```sh
python3 scripts/code-context-host.py --claude /absolute/test/prefix/node_modules/.bin/claude --agent target/debug/wk-agent
```

The harness creates an owned temporary repository, private configuration and loopback synthetic Anthropic-protocol endpoint. It clears inherited Claude/Anthropic settings and uses a nonfunctional test key; it never uses an account, global client profile, real project, cloud model or browser acknowledgement. The baseline must actually edit its synthetic target. Missing enrollment, a crashing hook and a timed-out hook must leave it unchanged. Client output is withheld on failure. Unsupported versions are rejected before the model/edit flow starts.

## Dependency advisory disposition

Both `wk-server` and `wk-agent` normally link `rsa 0.9.10` through `openidconnect 4.0.1`. Unsuppressed `cargo audit` fails with RUSTSEC-2023-0071; its current advisory has no patched version. The inspected OIDC consumer path constructs RSA public keys for signature verification. The advisory concerns timing of private-key operations; that is relevant applicability evidence, not an independent security clearance or permission to suppress the dependency.

Keep the established OIDC protocol implementation until a supported remediation or independently reviewed disposition is available. Replacing it with new homegrown token validation would introduce a separate security review obligation.
