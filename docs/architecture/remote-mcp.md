# Remote MCP

The same server exposes the standard SDK's stateless Streamable HTTP transport at `/mcp/{product}`. Eleven tools mirror the stdio bridge (including `knowledge.share_session`; the bridge also has two local-only tools, `workspace.folder` and `workspace.request_approval`, for approving a project folder from the agent): search, get, context, record, feedback, workspace status, environment schema, Jev assessment, overlap notices and advisory code-change context. Every HTTP request authenticates independently and checks membership in its route-bound product. Tool calls use the in-process knowledge service; bearer tokens are never forwarded to an upstream API. There is no shared mutable user session or global access token.

Production requires existing OIDC configuration plus `WK_MCP_RESOURCE=https://knowledge.example` (an HTTPS origin with no trailing slash). Set `WK_OIDC_AUDIENCE` to exactly that resource identifier and configure the identity provider to issue tokens for it. Protected-resource metadata is available at `/.well-known/oauth-protected-resource`; 401 responses advertise that URL in `WWW-Authenticate`. The optional `WK_MCP_CLIENT_ID` names the public client `wk-mcp login` signs in with; it is advertised as the extra metadata field `wk_mcp_client_id` and grants nothing (tokens are still verified against the single audience). The configured issuer supplies OAuth authorization/token endpoints and client registration. This application does not issue tokens or promise dynamic registration unsupported by the provider. No token refresh credentials are held by the resource server.

Use a TLS reverse proxy for the HTTP listener. Browser Origin handling follows the exact configured console origin; all other browser origins are rejected. CLI requests may omit Origin. Request bodies are bounded to 64 KiB. Stdio remains the fallback for clients without compatible remote OAuth support. Dev-mode integration tests use a synthetic bearer identity on loopback only; that is not production OAuth.

Synthetic integration passed for SDK initialize/discovery/search, invalid identity and forbidden browser origin. Session resumption/server-push notifications are not offered by this stateless deployment.

## Signing in

- **Stdio bridge.** `wk-mcp login` (authorization code with PKCE and a loopback redirect) reads the metadata above, requests the resource as an RFC 8707 `resource` parameter, stores only a refresh token in the OS credential store and lets `wk-mcp` renew access tokens silently. It requires an HTTPS server (or literal loopback), a resource equal to the server URL and exactly one authorization server, and rejects a JWT access token whose audience is not exactly the resource. See [MCP sign-in](../adapters/setup.md#mcp-sign-in-wk-mcp-login-and-native-remote-clients).
- **Native remote clients.** A client discovers the issuer from the metadata, needs a client at the provider (dynamic registration or a pre-registered one) and a token whose `aud` is exactly the resource. Against Keycloak 26.4.7 over a private CA, [Claude Code 2.1.15, the Cursor agent CLI 2026.05.24, the Cursor editor 3.25.9 (one user-driven run) and VS Code 1.142.0 (an automated run) passed sign-in, tool listing and silent renewal](../reviews/2026-10-19-remote-mcp-signin-results.md) once the provider allowed registration and defaulted the audience (a one-time, scripted realm step). Keycloak ignores the `resource` parameter, so the audience comes from a mapper, not from what the client asks for; a provider that honours `resource` must be configured to accept the exact string clients send (Claude Code and the Cursor CLI send the origin with a trailing slash). The server does not issue tokens, hold refresh credentials or accept more than one audience.
- **VS Code needs more than the others.** It registers three loopback and `vscode.dev` redirects (so those hosts go on the trusted list), sends `resource` as the origin without a trailing slash, asks for every scope the provider advertises, and refreshes any token with under 300 s left, so the access-token lifespan must be above 5 minutes (at Keycloak's default 300 s it fires dozens of refreshes per sign-in). The server's single-audience rule needed no change.
- **Not tested:** a model calling a tool through VS Code or Cursor, providers other than Keycloak, and public-CA providers.

Both tool lists (stdio and hosted) give every property an object schema: an untyped property produced the JSON-Schema literal `true`, which Claude Code 2.1.15 rejected, so it showed no tools at all. A regression test covers both servers.
