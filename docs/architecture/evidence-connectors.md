# Signed evidence ingestion

`wk-evidence /absolute/trust.json` reads a bounded envelope from stdin and applies it using the administrator database connection in `WK_DATABASE_URL`. `WK_OPERATOR_ORG` and `WK_OPERATOR_USER` identify a provisioned reviewer whose scope must cover the card. Keep this binary and the database credentials on the isolated connector service; it is not exposed as a public HTTP or MCP tool.

The envelope has exactly `key_id`, `payload` (a JSON string), and `signature_hex`. Sign the exact UTF-8 bytes of `payload` with the pinned Ed25519 key; reformatting the payload invalidates the signature. The payload includes `event_id` (UUID), `org`, `product`, `card_id`, `card_revision`, `issued_at`, `expires_at`, `evidence`, and optional `revoke`. Expiry must be within 15 minutes of issuance. The evidence shape is provider/reference/code_revision/kind/metadata, as described in backend operations. Test evidence requires a passed result and command/time/environment fields from the trusted connector.

Trust configuration maps key IDs to `public_key_hex`, `provider`, `org`, `product`, and an explicit `hosts` array. There are no wildcard hosts or token-provided keys. Keep trust configuration protected by deployment filesystem permissions; editing it changes the trust boundary. Provider references must be credential-free HTTPS URLs on the allowlist. No reference URLs are fetched by the importer.

A signed event UUID is a durable replay guard inside the evidence transaction. Replays and stale card revisions are rejected. A new code observation invalidates previous evidence for other code revisions; verification requires matching active code and passing-test evidence. A signed `revoke:true` receipt invalidates that provider's earlier claims and recomputes lifecycle without resurrecting stale runs. Superseded/deprecated cards cannot be promoted. Teammates receive only evidence references/freshness, not internal command or connector metadata.

The cryptographic envelope verifies the trusted producer, not the truth of arbitrary claims. Production CI/repository integrations must independently collect immutable commit identities and real test outcomes before signing. Synthetic tests cover tampering, unknown keys, expiry, replay, matching code/test promotion, source-revision invalidation, revocation and scope. No production signing key or live Git provider was configured.
