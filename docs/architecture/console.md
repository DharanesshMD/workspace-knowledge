# Developer console

React/TypeScript/Vite console in `web/`; build with `npm ci && npm run build`. Serve `web/dist` through the same HTTPS origin as the API (`WK_WEB_DIR`) and configure its exact `WK_CONSOLE_ORIGIN`.

Hosted sign-in uses the operator-configured OIDC provider, authorization code + PKCE, a browser-bound nonce/state transaction and an opaque HttpOnly cookie. No provider token reaches React or browser storage. `/v1/me` returns trusted identity and current permitted products; selecting another product clears the previous content and cancels pending requests. Sign out deletes this portal session and clears its cookie; it does not end the provider's own SSO session. Production without browser OIDC configuration shows setup-needed, without a token-paste fallback. Explicit development mode retains the memory-only bearer form.

Views currently include product search, authorized summary details, review queue, correction at expected revision, withdrawal, feedback, historical summaries, permission-filtered graph, current membership policy and metadata-only environment schemas. Static text rendering avoids active HTML from summaries. No conversation transcript or environment secret endpoint is provided. Native capture health remains available through local `wk-agent doctor`.

My context is the default hosted page. It lists only the signed-in developer’s current-scope summaries, supports structured manual notes, revision-checked edits, explicit review-copy submission and confirmed deletion. Filters apply to loaded pages. The separate owner store never feeds shared search, graph, activity or MCP. Ordinary review drafts remain visible to authorized reviewers. Team context browses only authorized published summaries with server-side author/service/date/file filters and cursor pages. It reuses the shared inspector and separately requests bounded activity reports with last-report/expiry times; there is no member directory or presence/productivity score. Device connection/settings and scoped administration are subsequent increments from the [portal roadmap](2026-10-10-hosted-developer-portal-plan.md).

Twenty-two browser regressions cover synthetic authorization, product switching, logout, setup failures, existing workflows, and desktop/390px layout. A real server/PostgreSQL/local OIDC provider acceptance also passed; [exact evidence and limitations](../reviews/2026-10-10-hosted-identity-acceptance.md). The real owner workflow also passed with both public and confidential local-provider clients; [owner acceptance](../reviews/2026-10-10-owner-context-acceptance.md). [Two-identity Team context acceptance](../reviews/2026-10-10-team-context-acceptance.md) also passed against the real local server and browser. Production-provider certification, physical expiry cleanup/restore integration and capacity testing remain open.

Owner-only collector synchronization is an explicit local choice: `wk-agent --state-dir /absolute/private/state owner-sync status`, `owner-sync enable --yes`, or `owner-sync disable`. It defaults off, pins scope/destination/device/credential account/model settings and membership revision, and never publishes automatically. A changed approval or configuration requires re-enabling. Status describes local consent; remote policy is not checked by the read-only status command. Synchronization uses the existing source/expiry/privacy gates, a 50-record rotating scan and a 20-second budget. A content-free success guard prevents repeated uploads across restarts while keeping the private draft available for existing local review.
